# 모델 계획

> 성능 수치는 **실제 데이터로 학습·평가한 결과만** 기록합니다. 합성 샘플 데이터로 얻은 수치는 기록하지 않습니다.
> 아래 회귀 수치는 `data/processed/training_dataset.csv` (2021-01 ~ 2026-08, 257,655건) 를
> 계약일 기준 시간순 70/15/15 로 나눠 측정한 값입니다. `python scripts/train_price.py` 로 재현됩니다.

## 1. 가격 회귀 (기능 A)
| 구분 | 내용 |
|---|---|
| 정답값 | `price_krw` (원). 학습에는 **직전월 시장지수 대비 로그 평당가**를 쓰고 예측값은 원으로 되돌립니다 (아래 §1.1) |
| 입력 변수 | `schemas.REGRESSION_FEATURES` + `REGRESSION_LOCATION_FEATURES` (자치구·동·단지) |
| 채택 모델 | `HistGradientBoostingRegressor` (`PriceRegressionModel("gradient_boosting")`) |
| 비교 모델 | `LinearRegression`, `DecisionTreeRegressor`, `RandomForestRegressor`. 새 모델은 `REGRESSOR_FACTORIES`에 등록 |
| 전처리 | Pipeline 안의 `ColumnTransformer`: 중앙값 대체 + 표준화 + One-Hot + 위치 타깃 인코딩. **학습 데이터에만 fit** |
| 지표 | MAE, RMSE, R², MAPE (`evaluation.metrics.regression_metrics`) |
| 실행 | `python scripts/train_price.py` |

기준선: **자치구 + 평형대(10㎡ 단위) 중앙값 조회**. 학습이 전혀 없는 방식이므로, 모델이
이걸 못 넘기면 모델을 쓸 이유가 없습니다.

측정 결과 (train 180,279 / valid 38,666 / test 38,710건, 아래 §1.1·§1.2 구성 적용)

| 모델 | 학습시간 | valid MAE | test MAE | R² | MAPE | 편향 |
|---|---|---|---|---|---|---|
| 기준선: 자치구+평형 중앙값 | — | 3.26억 | 3.59억 | 0.603 | 28.0% | −2.05억 |
| `linear_regression` | 2초 | 1.73억 | 1.90억 | 0.871 | 18.8% | +0.65억 |
| `decision_tree` | 4초 | 1.59억 | 1.69억 | 0.902 | 13.8% | −0.82억 |
| `random_forest` | 283초 | 1.45억 | 1.52억 | 0.925 | 12.5% | −0.79억 |
| `gradient_boosting` | 55초 | **1.41억** | **1.36억** | **0.935** | **11.5%** | −0.53억 |

**모델 선택 기준**: `scripts/train_price.py` 는 **valid MAE** 로 고릅니다. test 를 보고 고르면
test 가 더 이상 '한 번도 안 쓴 데이터'가 아니게 되므로, 점수가 실제보다 좋게 나옵니다.
그 규칙으로 `gradient_boosting` 이 선택됩니다 (valid 1.41 vs `random_forest` 1.45억).

저장되는 **배포본**은 위 표에서 두 단계를 더 거칩니다 (§1.3). 같은 test 구간 측정값입니다.

| 단계 | valid MAE | test MAE | R² | MAPE | 편향 |
|---|---|---|---|---|---|
| `gradient_boosting` (train 만) | 1.41억 | 1.36억 | 0.935 | 11.5% | −0.53억 |
| \+ 로그 복원 편향 보정 (×1.0102) | 1.38억 | 1.34억 | 0.937 | 11.5% | −0.41억 |
| \+ train+valid 로 재학습 ← **저장본** | (학습에 포함) | **1.12억** | **0.952** | **9.4%** | **+0.03억** |

모델끼리 비교할 때는 전부 train 만으로 학습한 **1.36억**을, 실제 배포본 성능으로는
**1.12억**을 쓰세요. 섞어 쓰면 비교가 깨집니다.

### 1.1 왜 '절대 가격'이 아니라 '시세 대비 상대가격'인가

처음에는 `price_krw` 를 그대로 맞혔습니다. 그런데 **트리 계열은 학습 때 본 범위 밖으로
외삽하지 못합니다.** 시간순 분할에서 test 구간(2026년)은 학습 구간(~2025-07)보다 가격이
높은데, 모델은 마지막으로 학습한 가격대에서 멈춥니다. 측정된 증상:

- test 편향(예측 − 실제) **−1.69억**, 그리고 그 편향이 2026-02 −1.26억 → 2026-08 −2.01억으로
  **시간이 갈수록 커졌습니다**.
- `contract_year`·`contract_month` 를 빼도 R² 0.807 → 0.806 (차이 없음).
- 직전월 시장지수를 **설명변수로** 추가해도 편향 −1.66억 (거의 그대로). 설명변수도 외삽이
  안 되기 때문입니다.

그래서 시점 흐름을 학습에 맡기지 않고, **지수로 직접 처리**합니다 (`models/market_index.py`).

- 지수 = 그 자치구의 **직전월** 평균 로그 평당가. 거래가 10건 미만인 자치구-월은 서울 전체
  평균으로, 그마저 없으면 마지막 알려진 값으로 대체합니다.
- 모델이 맞히는 값 = `log(가격/면적) − 지수` (= 그 시점 시세의 몇 배인가)
- 예측 = `exp(모델 출력 + 지수) × 면적`

결과: 편향 −1.69억 → **−0.67억**, 월별 추세도 사라졌습니다. R² 0.860 → **0.935**.

**시점 규칙에 대한 해명**: 지수는 계약일 기준 **직전월** 거래로만 만듭니다. 실거래가는
계약 후 30일 내 신고되므로, 예측 시점에 직전월 거래는 이미 공개돼 있습니다. 즉 예측
시점에 알 수 없는 정보는 들어가지 않습니다. 다만 test 구간의 지수는 test 구간 거래로
만들어지므로, 학습 구간만으로 지수를 고정한 **엄격 조건**도 함께 측정했습니다:
test MAE 1.97억 / R² 0.892 — 이 경우에도 절대가격 방식(2.07억 / 0.860)보다 낫습니다.
즉 **상대가격이라는 구조 자체가 더 맞고**, 최신 지수를 쓰면 더 좋아집니다.

### 1.2 위치를 어디까지 넣는가

자치구 25개만으로는 서울 아파트 가격을 설명하기 어렵습니다. 동(332개)·단지(약 7,900개)를
넣으면 좋아지지만, 원-핫으로는 변수가 폭발하고 `HistGradientBoosting` 의 범주형 직접
처리는 255개까지만 됩니다. 그래서 **'그 위치의 평균 가격수준' 숫자 하나로 요약**합니다
(`models/location_price.py`).

| 위치 수준 | test MAE | R² |
|---|---|---|
| 자치구만 | 2.63억 | 0.807 |
| + 동 | 2.41억 | 0.839 |
| + 동 + 단지 | 2.17억 | 0.866 |

누출 방지 장치 (테스트로 고정: `tests/test_location_price.py`)
- 값은 **학습 데이터에서만** 계산합니다.
- 학습 행 자신의 값은 **5겹 out-of-fold** 로 채웁니다. 자기 거래가 자기 설명변수에 섞이면
  학습 성능만 올라가고 실제 성능은 떨어집니다.
- 거래가 적은 위치는 전체 평균 쪽으로 평활하고, 학습에 없던 위치는 전체 평균을 씁니다.
  그 위치의 학습 거래 수를 함께 내보내므로 모델이 '이 값을 믿을 만한지' 판단할 수 있습니다
  (test 거래의 2.7% 가 학습에 없던 단지입니다).

⚠️ **분류에는 쓰지 않습니다.** `CLASSIFICATION_*_FEATURES` 는 `REGRESSION_*_FEATURES` 를
그대로 물려받으므로, 위치 변수는 `REGRESSION_LOCATION_FEATURES` 라는 별도 상수로 두었습니다.
분류 입력에는 `price_krw` 가 있어서, 단지 수준 기준가가 함께 들어가면 `price_ratio` 를
역산해 이상거래 레이블 규칙을 그대로 복원할 수 있습니다.

### 1.3 배포본을 만드는 세 단계

**(1) 하이퍼파라미터는 시간순 교차검증으로 고릅니다.**
처음에는 valid 한 구간만 보고 `max_leaf_nodes=31` 을 쓰고 있었는데, 근거가 없었습니다.
잎 개수를 늘려 가며 재 보니 **valid 는 끝까지 좋아지는데 test 는 127잎을 넘기면 나빠졌습니다**
(valid 1.444 → 1.350억, test 1.324 → 1.352억). valid 구간(2025-07~2026-02)이 test 구간
(2026-02~08)보다 학습 구간에 가까워서, 최근 패턴에 과적합한 모델을 과대평가한 것입니다.
여기서 127을 고르면 test 를 보고 고르는 것이라 반칙입니다. 그래서 **train+valid 안을
6개월 단위 4구간으로 나눠 폴드 평균**으로 골랐습니다.

| `max_leaf_nodes` | 폴드 평균 MAE | 표준편차 |
|---|---|---|
| 31 (이전 값) | 1.196억 | 0.202 |
| 63 | 1.152억 | 0.185 |
| 127 | 1.129억 | 0.198 |
| **255** (채택) | **1.108억** | 0.188 |

4개 폴드 전부에서 255가 가장 좋았습니다. `max_iter=800`, `learning_rate=0.05` 를 함께 씁니다.
(폴드는 2024-02~08, 2024-08~2025-02, 2025-02~08, 2025-08~2026-02. 각 폴드의 학습 구간은
그 앞 전체이고, test 는 선택이 끝난 뒤 한 번만 평가했습니다.)

**(2) 로그 복원 편향을 보정합니다.**
로그 평당가를 학습해 `exp` 로 되돌리면 평균이 아니라 **중앙값**이 복원됩니다. 로그를 씌우는
순간 분포가 눌리고, 되돌릴 때 위쪽 꼬리가 되살아나지 않아 예측이 체계적으로 낮아집니다.
잔차 분산의 절반을 지수로 올린 `exp(sigma^2 / 2)` 를 곱하면 그만큼이 복원됩니다
(`PriceRegressionModel.calibrate`). 계수 1.0102 는 **valid 에서만** 구합니다 — 학습 데이터의
잔차는 과적합 때문에 작아서 보정이 모자라고, test 에서 구하면 평가 대상을 보고 맞추는
것이라 반칙입니다.

**(3) 배포본은 train+valid 로 다시 학습합니다.**
valid 구간(최근 7개월)을 버리면 그 사이 거래된 단지를 못 본 상태로 예측하게 됩니다.
상대가격 구조가 시세 흐름은 처리해 주지만 **단지별 가격 수준은 그 단지 거래를 봐야** 알 수
있습니다. 넣으면 test MAE 1.34 → 1.12억, 편향 −0.41 → +0.03억이 됩니다. 월별 편향도
한쪽으로 쏠리지 않고 0 주변에 흩어집니다 (−0.69 ~ +0.57억). 보정계수는 valid 를 학습에
넣기 **전** 모델에서 구한 값을 그대로 가져오므로(`set_log_bias_factor`), test 정보는
어느 단계에도 들어가지 않습니다.

### 1.4 남은 과제
- API 단건 입력에 동·단지가 없으면 정확도가 **기준선보다도 낮아집니다.** 같은 모델에
  동·단지를 비우고 test 를 재면 MAE 1.41 → 4.18억, R² 0.935 → 0.499 (기준선 0.603)이고
  평균 3.6억을 낮게 부릅니다. 변수 중요도 2위가 `complex_id`(섞으면 MAE +2.52억)라서
  그걸 매 요청마다 버린 셈이었습니다. 동만 주고 단지를 빼면 4.85억으로 **더** 나빠집니다 —
  학습 때 본 적 없는 조합이기 때문입니다. 대책은 API 요청에 단지 선택 입력을 추가하고,
  프론트가 고를 수 있도록 자치구별 단지 목록을 내려주는 것입니다.
- 금리·규제 변수는 가격 정확도에 기여하지 않습니다. valid 8,000건으로 변수를 섞어 MAE
  증가량을 재면 `district` +3.26억, `complex_id` +2.52억, `area_m2` +2.37억 다음은 전부
  0.1억 미만이고, 금리 10종은 모두 +0.006억 이하, `reg_score_change` 는 −0.09억(섞으면
  오히려 좋아짐)입니다. 수집 자체는 기능 C(금리 시나리오)에 필요하지만, **가격 예측에
  기여한다고 쓰면 안 됩니다.**
- `random_state` 는 결과를 바꾸지 않습니다. `early_stopping=False` 에 표본추출이 없어
  5개 seed 가 모두 같은 값을 냈습니다. 재현성은 보장되지만 seed 분산은 보고할 것이 없습니다.
- 앙상블(`models/ensemble.py`)은 분류에만 쓰고 회귀에는 적용하지 않았습니다.
- `contract_year` 는 그대로 둡니다. 빼는 실험에서 valid 는 나빠지고(1.50 → 1.55억) test 는
  좋아져서(1.41 → 1.38억) 방향이 엇갈립니다 — 기여가 노이즈 수준이라는 뜻입니다. 선택
  규칙(valid)대로 유지하고, `CLASSIFICATION_FEATURES` 도 건드리지 않습니다.
- 그 결과 현재 날짜로 예측하면 `out_of_range_warnings` 가 `contract_year=2026 ... (외삽)`
  경고를 **매번** 냅니다. 값이 학습 범위 밖인 건 사실이지만, 가격 수준은 시장지수가
  처리하므로 예측이 그만큼 불안하다는 뜻은 아닙니다. 프론트에서 이 경고를 어떻게 보여줄지는
  UI 쪽 판단입니다 (`scenarios/interest_rate.py: out_of_range_warnings`).

## 2. 이상거래 의심 분류 (기능 B)
| 구분 | 내용 |
|---|---|
| 정답값 | `anomaly_label` (0 = 정상, 1 = 의심) — **미확보** |
| 입력 변수 | 자치구, 전용면적, 층, 건축연도, 건물연식, 계약 연·월, 기준금리, 자치구 규제 3종, 거래가격, ㎡당 가격 |
| 개별 모델 | `DecisionTreeClassifier`, `RandomForestClassifier`, `HistGradientBoostingClassifier` (Boosting) |
| 앙상블 | `VotingClassifier` (soft voting) — `ensemble.build_voting_model()` |
| 지표 | Precision, Recall, F1, Confusion Matrix (`classification_metrics`) |

### 확정된 레이블 기준 (2026-11-27)

규칙 기반 레이블을 씁니다. `label_anomalies(direction="below")` — 같은 자치구·평형대
기준가보다 **1단계 20%, 2단계 30% 이상 싼** 거래를 1 로 둡니다. 3·4단계는 기준가가
거칠어서 레이블을 달지 않습니다 (미판정).

**비싼 쪽은 뺐습니다.** 레이블을 만들 때 쓰지 않은 직거래 비율로 보면 (전체 2.74%):

| 후보 | 건수 | 직거래 비율 |
|---|---|---|
| 1단계 싸게 | 1,172 | 67.03% (24배) |
| 2단계 싸게 | 1,527 | 23.42% (8.5배) |
| 1단계 비싸게 | 2,121 | 3.88% (1.4배) |
| 2단계 비싸게 | 2,759 | 1.36% (**평균보다 낮음**) |

싼 쪽에는 직거래가 몰려 있는데 비싼 쪽은 그렇지 않습니다. 양쪽을 한 레이블로 묶으면
성격이 다른 두 집단이 섞입니다. 실제로 묶어서 학습하면 성능이 떨어집니다
(test F1 `both` 0.043 vs `below` 0.172).

레이블 기준은 학습 시점에 `--direction` 으로 정합니다. CSV 에 들어 있던 값을 그대로
쓰지 않습니다 — 어떤 기준으로 만든 레이블인지가 결과를 좌우하기 때문입니다.

### 모델이 규칙 기준선을 넘지 못합니다

학습이 전혀 없는 한 줄 규칙 **"직거래면 이상"** 과 비교하면 (test 구간, 문턱값 0.5):

| | Precision | Recall | F1 |
|---|---|---|---|
| **기준선: 직거래면 이상** | 0.363 | 0.378 | **0.371** |
| decision_tree | 0.107 | 0.209 | 0.142 |
| random_forest | 0.587 | 0.055 | 0.100 |
| hist_gradient_boosting (선택) | 0.265 | 0.153 | 0.194 |
| voting | 0.350 | 0.144 | 0.204 |

네 모델 모두 기준선의 절반 수준입니다. **이유는 레이블 정의에 있습니다.** 레이블은
`가격 < 기준가 × 0.8` 인데, 분류 입력 44개에 **기준가가 없습니다.** 기준가를 주면
모델이 레이블 공식을 그대로 되계산하게 되므로 일부러 뺀 것입니다. 그래서 모델은 규칙을
복원하지 못하고 상관있는 흔적만 줍습니다 — 모델이 1 로 뽑은 거래의 98~100%가
직거래입니다. 직거래 변수를 빼면 F1 이 0.086 으로 더 떨어져, 그 변수가 거의 전부입니다.

문턱값을 낮춰도 달라지지 않습니다. valid 에서 F1 이 가장 높은 0.40 을 써도 test F1 은
0.194 로 0.50 과 같습니다. 그래서 0.5 를 유지합니다.

**이것은 결함이 아니라 결과입니다.** 가격 편차로 레이블을 만들면서 가격 기준을
입력에서 빼면, 지도학습이 할 수 있는 일이 남지 않습니다. 다음 중 하나를 골라야 합니다.

1. 가격에서 파생되지 않는 레이블로 바꾸기 — 해제(취소) 여부, 단기 재매매 등
2. 비지도 이상탐지로 범위 변경 (IsolationForest 등) — 지도교수·팀 협의 필요
3. 현 상태를 유지하고 **기준선 비교를 결과로 보고** — 규칙 하나가 모델을 이긴다는
   사실 자체가 관찰이며, 회귀에서 기준선을 넘긴 것과 대비됩니다

현재는 3번 상태입니다. `scripts/train_anomaly.py` 가 매번 기준선을 함께 출력하고
`anomaly_model_metrics.json` 의 `baseline_direct_deal` 에 기록합니다.
### 학습 및 백엔드 연동

1. 레이블은 학습 시점에 `--direction` 으로 만듭니다 (기본 `below`). CSV 의 `anomaly_label` 값은 덮어씁니다. `0`은 정상, `1`은 이상거래 의심, 빈 값은 미판정입니다. 저장소의 `TEST_ONLY` 샘플 122행은 학습에 쓸 수 없습니다.
2. `configs/settings.yaml`의 `classification.training_enabled`는 `true`입니다. 저장소 루트에서 실행합니다. `--label-source`에는 레이블 기준과 확정 날짜를 적습니다.

   ```bash
   python scripts/train_anomaly.py --label-source "label_anomalies(direction=below): 기준가 대비 1단계 20%, 2단계 30% 이상 싼 거래. 2026-11-27 확정."
   ```

3. 전체 거래를 계약일 기준으로 분할한 뒤 구간별로 레이블이 있는 행을 사용합니다. 각 구간에서 정상과 의심 거래가 모두 필요합니다. 결측 대체 및 인코딩은 학습 구간에서만 적합합니다.
4. 개별 모델 3종과 동일 가중치 soft voting에 공통 임계값 0.5를 사용합니다. 검증 F1이 가장 높은 모델을 선택합니다. 동률이면 Recall, Precision, 모델 선언 순서로 결정합니다. 선택 후 테스트 구간에서 네 모델의 Precision, Recall, F1 및 혼동행렬을 계산합니다. 행렬의 행은 실제값, 열은 예측값이며 순서는 `[0, 1]`입니다.
5. 기본 출력은 `models/anomaly_model.joblib`와 `models/anomaly_model_metrics.json`입니다. JSON 에는 `label_direction` 과 규칙 기준선(`baseline_direct_deal`)도 함께 들어갑니다. joblib에는 선택된 모델과 전처리기가 들어갑니다. JSON에는 모델별 검증·테스트 지표, 구간별 계약일 범위, 클래스별 건수 및 미판정 건수, 레이블 출처가 들어갑니다.

API 서버는 시작할 때 설정된 모델 파일을 불러옵니다. [API 계약](API_CONTRACT.md)의 `POST /predict/anomaly`에 거래 조건과 원 단위 실제 거래가격 `price_krw`를 보내면 `is_suspicious`, `suspicion_score`, `threshold`, `model_name`을 반환합니다. 파이썬에서는 `AnomalyClassificationModel.load(path)`로 모델을 불러오고, 해당 모델의 `feature_columns`를 포함한 DataFrame에 `predict` 또는 `predict_proba`를 호출할 수 있습니다. 학습 입력은 API 요청에서 제공하거나 파생할 수 있는 변수로 구성합니다.

## 3. 시간순 검증
- 분할: `evaluation.split.time_based_split` (비율, 기본 70/15/15) 또는 `split_by_dates` (경계 날짜 지정)
  - 같은 계약일의 거래는 같은 구간에 들어갑니다. train < valid < test 순서를 지킵니다.
- 하이퍼파라미터 조정: train 데이터 안에서 `expanding_window_splits` (확장 윈도우 교차검증)를 사용합니다.
  - 일반 `KFold`나 셔플 분할은 **사용하지 않습니다** (미래 데이터 누출).
  - 가격 회귀에 실제로 적용한 구성과 결과는 §1.3 (1)에 있습니다. valid 한 구간만 보면
    복잡한 모델을 과대평가한다는 것을 측정으로 확인했습니다.
- test 데이터는 최종 보고 직전에 한 번만 사용합니다.
- 분할 기준인 계약일과 입력 변수인 계약 연·월은 별개입니다. 입력 변수로 쓰더라도 분할은 항상 계약일 기준으로 합니다.
- 금리·규제 변수는 계약일 시점에 유효한 값만 붙입니다 (`DATA_SCHEMA.md` §4).

## 4. 금리 시나리오 (기능 C)
- `scenarios.interest_rate.compare_interest_rate_scenario(model, features, before, after)`
- 금리를 뺀 나머지 조건은 그대로 두고, 같은 모델로 두 번 예측해 차이와 변화율을 계산합니다.
- 입력값이 학습 데이터의 범위를 벗어나면 warning을 추가합니다 (`model.feature_ranges`).
- 이 결과는 **인과효과가 아닙니다.** 선형 모델에서는 금리 계수가 그대로 나타나고, 트리 모델에서는 학습 구간 밖에서 예측값이 변하지 않을 수 있습니다. 이 한계를 UI에도 표시합니다.
- 추가할 기능 (feature/scenario): 여러 금리 값에 대한 연속 비교(sweep), 결과 시각화

## 5. 향후 12개월 가격 예측 (기능 E)

### 예측 대상이 하나로 줄어든다

회귀가 절대가격이 아니라 **시세 대비 상대가격**을 학습하므로 (§1.1):

```
log(가격 / 면적) = 모델출력 + 시장지수(자치구, 월)
```

모델출력은 "이 아파트가 그 시점 시세 대비 어느 수준인가" 라서 **시점과 무관**합니다.
시점은 전부 시장지수가 들고 있습니다. 따라서 미래 가격 예측은 **시장지수 예측 하나**로
줄어듭니다. 25개 자치구의 월별 시계열만 내다보면 자치구 지수도 특정 단지 가격도 같이
나옵니다. 구현은 미래 달까지 연장한 지수를 만들어 회귀 모델에 바꿔 끼우는 것입니다
(`MarketIndexForecaster.extend` → `PriceRegressionModel.predict_with_market`).

### 추세를 연장하면 안 된다

rolling-origin 백테스트 (기준시점 43개 × 자치구 25개, 로그 MAE 를 퍼센트로 환산):

| 방법 | 1개월 | 3개월 | 6개월 | 12개월 | 전체 |
|---|---|---|---|---|---|
| 직전값 그대로 | 4.7% | 6.0% | 7.4% | 8.7% | 6.9% |
| 최근 3개월 평균 | 4.6% | 5.8% | 6.7% | 8.7% | 6.6% |
| 최근 1년 기울기 연장 | 5.0% | 6.8% | 8.9% | **11.8%** | 8.4% |
| 최근 2년 기울기 연장 | 4.8% | 6.2% | 7.8% | 9.9% | 7.4% |
| **자치구 수준 + 서울 감쇠추세** (채택) | **4.6%** | **5.6%** | **6.4%** | **8.3%** | **6.4%** |

최근 추세를 그대로 연장하면 **아무것도 안 하느니만 못합니다.** 월간 변화의 자기상관이
+0.006 이라 지난달 움직임에 다음 달 정보가 없습니다. 월 평균 상승 +0.29% 에 표준편차
3.04% 로 잡음이 신호의 10배입니다.

추세는 **자치구별로 재지 않고 서울 전체에서 잽니다.** 거래가 적은 자치구(종로구·중구는
월간 변화 표준편차가 노원구의 4배)의 기울기는 시세가 아니라 '그 달에 어떤 단지가
거래됐나' 를 재게 됩니다. 자치구 수준(최근 3개월 평균)만 자치구에서 가져옵니다.
감쇠계수 0.8 로 지평이 길수록 추세 기여를 줄입니다.

### 구간을 반드시 같이 준다

예측값 하나만 내놓으면 거짓말이 됩니다. 구간은 두 몫을 제곱합으로 더해 만들고
(성격이 다른 오차입니다), 80% 범위로 보여줍니다.

1. **시점과 무관한 몫** — 같은 조건이라도 거래마다 가격이 다릅니다. 회귀의 valid
   로그잔차 산포 0.143 → 약 ±20%
2. **시세를 내다보는 몫** — 백테스트에서 잰 지평별 산포. 1개월 0.063, 12개월 0.096

대치동 은마 84.9㎡ 12층 기준 12개월 뒤 구간은 **±25%** 이고, 그 가운데 ±20%p 가 1번
몫입니다. **멀리 보는 것이 어려운 게 아니라, 애초에 개별 거래 편차가 큽니다.** 화면에도
이 분해를 같이 적습니다.

### 금리는 넣지 않는다

금리 변수가 가격 정확도에 기여하지 않는다는 것이 측정됐습니다 (§1.4). 미래 금리를
가정해서 예측에 넣으면 근거 없는 숫자가 됩니다. 금리 시나리오(기능 C)는 "금리가 이러면
어떻게 될까" 라는 **what-if** 로 그대로 두고, 전망과 섞지 않습니다.

### 쓰는 법

API 는 `POST /forecast/price` 입니다 ([API 계약](API_CONTRACT.md)). 예측기는 저장된
가격 모델 **안에 들어 있는 시장지수**로 만들기 때문에 원본 CSV 가 필요 없고, 모델과
지수가 어긋날 일도 없습니다 (`MarketIndexForecaster.from_index`, 0.2초).

### 금리 시나리오(기능 C)가 재는 것

모델의 금리 반응은 **계단**입니다. 대치동 은마 84.9㎡ 12층 기준:

| 기준금리 | 예측 |
|---|---|
| 0.5 ~ 2.5% | 약 37.7억 (거의 평평) |
| 2.5 → 2.75% | **−10.6%** (분기 하나) |
| 2.75 ~ 3.5% | 약 33.3~33.8억 |
| 3.5% 초과 | 3.5% 와 **완전히 동일** |

학습 데이터의 기준금리가 0.5~3.5% 열두 값뿐이라 그 밖은 트리가 구분하지 못합니다.
자치구별 반응도 제각각입니다 (2.5→3.5% 에서 강남 −11.6%, 마포 −2.0%, 송파 −0.8%,
노원 −0.6%).

그래서 응답에 **관측 범위 전체의 곡선**을 같이 돌려주고 화면에 그립니다. 숫자 하나만
보여주면 매끄러운 반응으로 읽히지만, 곡선을 보면 계단과 평평한 양 끝이 그대로
드러납니다. 범위 밖 요청에는 "경계와 같은 답" 이라고 명시하고, 큰 계단이 있으면 어느
구간에서 몇 % 움직이는지 경고에 적습니다.

이 기능은 **금리의 인과효과를 재지 않습니다.** 금리 변수는 가격 정확도에 기여하지도
않습니다 (§1.4). 학습 데이터에서 그 금리대에 함께 나타난 특징을 반영할 뿐입니다.

### 남은 과제

- 예측 대상이 **단지 수준의 시세 흐름**은 반영하지 못합니다. 재건축 추진 같은 단지별
  사정은 자치구 지수에 묻힙니다.
- 감쇠계수 0.8 과 창 길이 24개월은 백테스트에서 고른 값이지만, 탐색 범위가 좁습니다.
- 최대 24개월까지 받지만 12개월을 넘는 구간은 표본이 적어 산포 추정이 거칠어집니다.
