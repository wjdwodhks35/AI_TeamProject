국토교통부 자료는 계약이 해제되면 **원본 행을 남기고 해제 행을 한 줄 더** 넣습니다.

## 6. 규제 결합

공개 API가 없어 고시를 직접 찾아 `configs/regulation_events.csv`에 **27건**을 정리했습니다.

| 종류 | 건수 | 처리 |
|---|---|---|
| 자치구별 규제 (조정대상지역·투기과열지구·토지거래허가) | 10건 | `to_regulation_history` → 구 × 기간 테이블 |
| 전국 공통 규제 (DSR·스트레스DSR·주담대한도·양도세중과·정책대출·만기연장제한) | 10건 | `to_national_regulation_state` → 변경일 × 상태 테이블 |
| 상태로 표현할 수 없는 발표 | 7건 | 근거만 기록 (총량규제 강화, 세제개편 방향, 지방 해제 등) |

전국 공통 규제는 자치구별로 갈리지 않으므로 기준금리처럼 **변경일 기준**으로 붙입니다. 월 단위로
뭉개면 10·15 대책이 10월 1~14일 계약에도 붙어 미래 정보가 섞입니다. DSR은 0/1이 아니라 단계가
올라가고(0→1→2→3) 주담대 한도는 억 단위 금액(99→6→4)이라 0/1 구간 테이블에 담을 수 없습니다.

**규제 점수는 그 시점에 걸려 있는 규제의 가중합입니다.** 누적 합계로 만들면 값이 한 방향으로만
움직여서 모델이 규제가 아니라 경과 시간을 학습합니다. 상태 기준으로 계산하면 경과 개월수와의
상관이 강남구 -0.763, 노원구 -0.443, 종로구 -0.448이고, 같은 달에도 자치구끼리 최대 5.0점
벌어집니다. 시간축과 분리된 변수라는 뜻입니다. 가중치는 `schemas.REGULATION_WEIGHTS`에 있고
우리가 정한 값이므로 팀 합의가 필요합니다.

**거래량이 전월 대비 ±35% 넘게 변한 22개월 중 13개월이 규제로 설명됩니다.**

**지역 규제의 효과가 뚜렷합니다.** 강남3구가 전체 거래에서 차지하는 비중입니다.

```

2025-07   22.1%
```

같은 서울 안에서 한 달 만에 비중이 4분의 1로 줄었습니다. 전국 공통인 금리로는 설명할 수 없고,
자치구별로 값이 다른 규제 변수만 설명할 수 있는 움직임입니다.

설명되지 않는 9개월은 대부분 **규제 시행 직전의 막차 수요**입니다 (2025-06에 12,619건, 2026-05에
9,283건으로 연중 최고를 찍고 다음 달에 꺾임). "규제 시행 D-30" 같은 변수를 넣으면 잡을 수 있습니다.

오히려 평균보다 직거래가 **적습니다**. 시세를 띄우는 조작은 대개 계약 해제로 끝나고 그 행은 이미
제거했으므로, 남은 고가 거래는 리모델링·고층·조망 같은 정상 사유가 대부분입니다. 반대로 싸게
넘기는 거래는 완결되어 자료에 남습니다. `label_anomalies(direction=...)`로 바꿀 수 있고 기본값은
`"below"`입니다.

| 항목 | 값 |
|---|---|
| 레이블 가능 (1·2단계) | 163,495건 (63.5%) |
| 이상거래 | 2,699건 (**1.65%**) |
| 레이블 없음 | 94,160건 (3·4단계 또는 기준가 없음) |

## 8. 레이블 검증

레이블을 우리가 정했기 때문에, 우리 기준으로 평가하면 순환입니다. **밖에서 주어진 사실**과 겹치는지
확인했습니다.

| | 이상거래 (2,699건) | 정상 거래 (160,796건) | 배수 |
|---|---|---|---|
| 직거래 비율 | **42.68%** | 2.05% | **20.8배** |
| 관외 중개 비율 | **7.00%** | 2.13% | 3.3배 |

**이상거래로 뽑힌 2,699건 중 42.68%가 중개사를 거치지 않은 직거래였습니다.** 정상 거래는
2.05%입니다. 1단계만 보면 67.03%까지 올라갑니다. 서로 다른 방법으로 찾았는데 같은 거래를
가리킵니다.

직거래 여부는 레이블을 만들 때 쓰지 않았습니다. 다만 입력 변수로도 쓰면 검증으로서의 독립성이
사라지므로, 모델을 만들 때 **넣은 경우와 뺀 경우를 비교**해야 합니다.

### 해제율로 검증할 때의 제약

해제는 계약 후 한참 뒤에 일어납니다.

| 계약 후 경과 | 최종 해제 중 드러난 비율 |
|---|---|
| 1개월 | 46.6% |
| 3개월 | 83.9% |
| **6개월** | **96.5%** |
| 12개월 | 99.1% |

최장 1,845일(약 5년)이었고, 1년 넘는 건은 127건(0.88%)입니다. 장기 해제는 직거래에 몰려 있습니다
(최장 5건 중 4건).

따라서 해제율로 검증할 때는 **최근 2~3개월을 제외**해야 합니다. 우리가 뽑는 거래에 직거래가 많이
섞여 있고 직거래는 해제가 늦게 드러나므로, 최근 구간에서는 우리 쪽 해제율만 덜 차서 결과가 나쁘게
나옵니다.

## 9. 재현성

| 검사 | 결과 |
|---|---|
| 같은 원본으로 다시 돌렸을 때 결과가 같은가 | 예 (난수 사용 없음) |
| 수집을 중단 후 재실행하면 이어받는가 | 예 (파일 존재 여부로 판단) |
| 기간을 늘려도 기존 데이터를 다시 받지 않는가 | 예 |
| 학습 데이터 생성을 중단 후 재실행하면 이어받는가 | 예 (자치구별 CSV가 원본보다 새것이면 건너뜀) |
| 학습 데이터 생성이 외부 네트워크를 쓰는가 | 아니오 (`data/raw`만 읽음) |
| 테스트가 외부 네트워크를 호출하는가 | 아니오 (`tests/conftest.py`가 차단) |

**참고 — Windows에서 `tests/test_api.py`가 11건 실패합니다.** `conftest.py`의 네트워크 차단이
`socket.socket.connect`를 막는데, Windows의 `socket.socketpair()`는 AF_UNIX가 없어 127.0.0.1로
TCP 연결을 맺습니다. `TestClient`가 이벤트 루프를 만들 때 그 경로를 타서 차단에 걸립니다. 리눅스는
AF_UNIX를 써서 connect를 하지 않으므로 CI(`ubuntu-latest`)에서는 통과합니다. API 담당 영역이라
여기서 고치지 않았습니다.

## 10. 다른 담당자에게 전달

**머신러닝 담당자**

- 데이터 만들기: `python scripts/build_dataset.py --label` → `data/processed/training_dataset.csv`
  (257,655행 × 66칸). 원본만 있으면 네트워크 없이 돌아갑니다.
- 입력 변수: `schemas.REGRESSION_FEATURES`, `schemas.CLASSIFICATION_FEATURES`
- 금리는 **수준이 아니라 변화량**을 쓸 것. 10종 × (수준·12개월·3개월) 이 들어 있고 기본 입력에는
  `base_rate` 수준만 예외로 남겨 두었습니다 (금리 시나리오가 그 컬럼을 요구합니다).
- **검토해 볼 것:** 대출금리는 6개월 전 변화가 지금 가격과 더 강하게 맞물립니다 (주담대 동시점
  -0.435 → 6개월 선행 -0.737). 선행 변수를 넣을지는 모델 담당자가 정하고, 현재 파이프라인은
  동시점과 3개월 변화만 붙입니다.
- 레이블은 `peer_tier`가 1 또는 2인 163,495건만 사용하고, 그중 이상거래는 2,699건(1.65%)입니다.
  **기준가보다 싼 쪽만** 봅니다 (비싼 쪽은 신호가 없습니다 — 8절). 정의는 합의 필요.
- **입력 금지:** `peer_median_price_krw`, `price_ratio`, `peer_tier` — 레이블을 역산할 수 있음
- 기간 한정: `is_direct_deal`을 쓰면 2022년 이후 (2021년 자료에는 거래유형이 없어 14.9%가 빈칸)
- 기준선: 지역·평형별 중앙값을 먼저 재고 모델이 그것을 이기는지 볼 것

**백엔드 담당자**

- 입력 형식: 자치구명(한글), 계약일(`YYYY-MM-DD`), 면적(㎡), 층(정수, 음수 가능)
- 금리 시나리오는 사용자가 **수준**(예: 3.0%)을 넣고, 내부에서 **현재 대비 변화량**으로 바꿔 모델에 전달
- 슬라이더 범위는 현재 ±1.5%p로 제한. 학습 범위를 벗어나면 트리 모델이 끝값을 반복함
